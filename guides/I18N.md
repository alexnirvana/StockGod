# Internationalization

[English](I18N.md) · [Chinese](I18N_CN.md)

Stock God 0.5 supports English (`en`) and Simplified Chinese (`zh-CN`) across the interface, five lessons, quizzes, review cases, onboarding, charts, and API feedback.

## Choosing a language

The sign-in page and application toolbar include a language selector. Before sign-in, the browser uses its saved preference or browser language. English browser variants use English, Chinese variants use Simplified Chinese, and other browser languages use English. An existing account's saved preference takes precedence after sign-in.

Authenticated changes are stored in `players.locale`. Existing accounts migrate to Simplified Chinese. Changing the language does not change answers, scores, rewards, transactions, or user-written names and reflections. Dates use China time in both languages, and monetary values remain CNY; changing language never converts currency.

## Resource locations

| Resource | Location |
| --- | --- |
| i18next setup and locale helpers | `frontend/src/i18n/index.ts` |
| Interface translations | `frontend/src/i18n/en.json` |
| English lesson bodies | `content/courses/en/*.md` |
| API, quiz and review translations | `content/locales/en.json` |
| Response localization and language negotiation | `backend/src/stock_god/i18n.py` |

The current interface uses the canonical Chinese text as its i18next key. Chinese resources are derived from those keys; English values live in the JSON catalog. Use named interpolation for full sentences, rather than assembling grammatical fragments. All components rendering translations subscribe to locale changes through `useLocale()`.

The API negotiates `Accept-Language`, returns `Content-Language`, and varies responses by language. Only allowlisted presentation fields are translated. Grading uses stable question indices and original content; idempotent responses are translated when read. The JSON export preserves canonical audit records, including original system text. User-entered text is never machine-translated.

## Adding another locale

1. Add its locale code and display label to the frontend locale helpers and selector; register its i18next resource.
2. Translate every interface key, all five lesson bodies, and every quiz, review, rule, and system message. Preserve placeholders and answer ordering. Rebuild the bundled narration for changed text, as described in [spoken explanations](NARRATION.md).
3. Extend the backend locale validator, language negotiation, and resource loading. Keep the persisted locale code within the existing 16-character column, or add a migration.
4. Keep query caches separated by language and account; verify sign-in restores the saved locale.
5. Extend translation coverage tests, then check desktop and mobile layouts, dialogs, error states, and onboarding in the new language.

Missing translations currently fall back to canonical Chinese. Coverage tests guard all static frontend keys and every graded quiz/review case; new content should not ship without matching translations.

```sh
npm --prefix frontend test
npm --prefix frontend run build
```
